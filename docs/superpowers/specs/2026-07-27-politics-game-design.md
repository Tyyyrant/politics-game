## 一、游戏概述

### 1.1 一句话描述

一款以中国省级官场为背景的回合制派系政治博弈游戏。玩家扮演一位省委常委，通过经营派系、攻略人大席位、操纵法案、查处对手，最终当选省长。

### 1.2 核心体验

- **派系经营**：管理你的嫡系干部网络，维持忠诚度，扩张势力
- **信息博弈**：公开信息可见，隐藏信息需花代价「打探」
- **策略深度**：资源分配、行动优先级、长期规划 vs 短期应变
- **叙事氛围**：事件卡故事化文案 + 回合简报 + 结局文本，轻叙事包装

### 1.3 技术定位

- **类型**: 单人 vs AI（未来可扩展本地多人热座）
- **平台**: Steam（Windows + macOS）
- **框架**: Electron + 纯 JavaScript（DOM 渲染 v1，预留 Canvas 迁移接口）
- **存档**: 本地 JSON 文件
- **胜利条件**: 10 轮后人大席位过半（≥14/27），含提前淘汰机制

### 2.2 资源系统

#### 2.2.1 部门资源

每个部门按职级产出资源（每轮刷新）：

| 职级 | 资源产出 |
|------|----------|
| 副部 | 10 |
| 正厅 | 6 |
| 副厅 | 4 |
| 正处 | 2 |
| 副处 | 1 |

资源类型 = 部门名（如「发改委资源」「公安厅资源」「组织部资源」）。

**特殊规则**：
- 政府办公厅资源 = 任意政府部门资源（1:1 等价兑换）
- 党委办公厅资源 = 任意党委部门资源（1:1 等价兑换）
- 通过《跨部门协作条例》后，政府/党委资源可 1:1 互通（持续 3 轮）

#### 2.2.2 影响力

每两轮按职级获取一次：

| 职级 | 影响力 |
|------|--------|
| 副部 | 10 |
| 正厅 | 6 |
| 副厅 | 4 |
| 正处 | 2 |
| 副处 | 1 |

影响力用途：拜访人大席位（1 影响力/次）、锁定席位（10-20 影响力/席）、打探信息（2-3 影响力）、提升忠诚度（10 影响力 +1）。

**换算**：5 影响力 = 1 通用资源。

#### 2.2.3 可用资金（灰色收入）

通过商人标记或国资委变现获取。用于：收买对手干部（1 资金 +1 忠诚度）、直接锁定席位（1-6 笔）。不留审计痕迹。

#### 2.2.4 纪委标记

每 2 轮自动累积 1 个。用于查办干部（副处 1、正处 2、副厅 3、正厅 4）和解除查办。

### 2.3 忠诚度系统

#### 2.3.1 基础规则

- 除派系首领外，所有成员有忠诚度（4-9）
- 忠诚度影响：被收买难度、个人追求完成效率
- 提升方式：10 影响力或 1 资金 → +1 忠诚度；完成个人追求 → +2~3 忠诚度
- 可被其他派系用资金/影响力收买（忠诚度越低越便宜）

#### 2.3.2 特质系统

| 特质 | 效果 |
|------|------|
| 心腹嫡系 | 初始忠诚度 8，被收买费用翻倍 |
| 曾受提拔 | 忠诚度不会自动下降，被提拔后 +2 忠诚 |
| 利益共同体 | 忠诚度不会下降，不会被收买 |
| 校友 | 加入时 +1 忠诚度 |
| 安排工作 | 完成该任务 +1 忠诚度 |
| 小孩升学 | 完成该任务 +2 忠诚度 |
| 购买新房 | 完成该任务 +3 忠诚度 |
| 政治追求 | 升任对应职级 +2~3 忠诚度 |
| 结识贵人 | 加入新派系 +2 忠诚度（2 轮后 -2） |

### 2.4 人大席位系统（核心胜利条件）

#### 2.4.1 席位机制

- 共 27 个 NPC 人大代表席位，每个席位 = 1 张省长选票
- 每个席位绑定一个隐藏任务
- 拜访：消耗 1 影响力 → 查看任务内容 → 启动攻略（将该席位暂时放到玩家面前）
- 完成：2 轮内完成指定任务 → 锁定席位（归属永久固定）
- 超期：2 轮未完成 → 席位退回人大格（其他玩家可攻略）
- 抢夺：对手消耗 2 影响力 + 双倍资源 → 夺取你未完成的席位
- 直接锁定：10-20 影响力或 1-6 笔资金，不做任务直接锁

#### 2.4.2 任务类型

| 任务 | 所需资源 | 消耗 |
|------|----------|------|
| 安排子女入学 | 教育资源 | 1-3 |
| 安排子女国企工作 | 国资委资源 | 1-3 |
| 保释朋友 | 公安/政法委资源 | 2 |
| 促成商人项目 | 国资/住建/发改资源 | 2-3 |
| 积累人脉 | 任意资源 | 2 |

### 2.5 法案系统

#### 2.5.1 投票机制

- 每轮结束阶段，从法案牌堆抽 1 张
- 各派系宣布支持/反对/弃权
- 投票权重：正厅 ×1.5 + 副厅 ×1，首领不参与
- 通过条件：总票数 > 50%
- 奖励：支持方获影响力（副部 10、正厅 6）
- 惩罚：未通过则反对方获双倍影响力，支持方资源减半

### 2.8 纪委查处机制

**骰子判定**（d6）：

| 点数 | 结果 |
|------|------|
| 1-2 | 无证据，无效果 |
| 3-4 | 嫌疑状态（1 轮后重新投掷） |
| 5-6 | 发现证据（1 轮后解除职务；若已有证据可直接查处） |

**消耗**：

| 目标职级 | 查处消耗 | 解除消耗 |
|----------|----------|----------|
| 副处 | 1 标记 | 2 标记 |
| 正处 | 2 标记 | 5 标记 |
| 副厅 | 3 标记 | 7 标记 |
| 正厅 | 4 标记 | 10 标记 |

政法委可在任何查处环节消耗 4 资源重投骰子 1 次。

### 2.9 商人/受贿系统

- 通过事件或消耗 2 影响力触发「商人上门」
- 获得一个受贿标记（随机标注数字 1-6）和等额可用资金
- 纪委每轮可消耗 1 资源对受贿派系进行「纪委检查」
- 投骰子若数字与标记数字相同 → 检查成功，被检查派系需移交对应数量的干部
- 标记数字与干部职级对应：1=副处，2=正处，3-4=副厅，5-6=正厅
- 检查结果可被纪委和政法委更改

|----------|----------------|
| 副处 | 5 |
| 正处 | 8 |

可用本机关资源抵扣（如公安厅任用干部可用公安资源抵扣）。

```
    ┌────────────────────────────────────────────────┐

    │  每个派系依次执行：                               │
    │  a. 抽取并处理事件卡（强制）                       │
    │  b. 资源刷新（下属单位按职级产出）                  │
    │  c. 党校培训（偶数轮额外获得 2 随机资源）            │
    │  d. 自由行动（可组合执行多项）                     │
    │  e. 冲突响应（其他派系可介入席位抢夺/法案干扰等）     │
    └────────────────────────────────────────────────┘
             ▼
┌─────────────────────────────────────────────────┐
│  ③ 法案集中处理（全体同步）                         │
│  · 抽 1 张法案                                    │
│  · 各派系宣布立场并投票                             │
│  · 结算结果与影响力奖励                             │
└────────────┬────────────────────────────────────┘
             ▼
┌─────────────────────────────────────────────────┐
│  ④ 清理阶段（全体同步）                            │
│  · 超期人大席位退回                                 │
│  · 持续效果倒计时 -1                               │
│  · 查处状态推进                                    │

│  · 检查胜负条件                                    │
│  · 轮次 +1                                       │
└─────────────────────────────────────────────────┘
```

## 四、信息可见性（方案 B — 部分隐藏）

### 4.1 公开层（始终可见）
- 各派系首领职级和部门
- 各派系公开成员名单（姓名+部门+职务）
- 已锁定人大席位归属
- 法案投票结果
- 当前轮次和顺位
- 已发生的查处结果
- 生效中的法案效果

### 4.2 推断层（可推测但不直接显示）
- 谁正在攻略某人大席位（可见拜访行为）
- 干部被纪委标记嫌疑（公开通知但不说细节）
- AI 资源多寡（观察行动频率和类型）

### 4.3 隐藏层（需消耗行动获取）
- **打探席位任务**（2 影响力）：查看对手席位任务内容和剩余轮数
- **打探干部忠诚度**（2 影响力/1 公安资源）：查看某成员忠诚度和特质
- **打探资源**（3 影响力）：查看目标派系当前资源数量

### 4.4 秘密层（无法直接获取）
- 对手的受贿标记数字
- AI 的下一步行动意图
- AI 的性格参数具体数值

### 4.5 己方信息
玩家自己派系的一切完全透明：忠诚度、资源精确数字、受贿标记内容、正在攻略的席位任务。

### 4.6 AI 信息对称
AI 同样遵守信息规则，不会作弊。AI 需要打探时必须消耗资源。日志会记录「Ch 派人打探了你的席位任务」。

## 五、AI 系统（性格底色 + 目标驱动）

### 5.1 性格参数

```javascript
// 纪委书记 Ch — 激进执法型
{ aggression: 0.8, cooperation: 0.3, riskTolerance: 0.6 }

// 组织部长 MI — 稳健经营型
{ aggression: 0.3, cooperation: 0.7, riskTolerance: 0.3 }

// 公安厅长 Wa — 暴力压制型
{ aggression: 0.9, cooperation: 0.2, riskTolerance: 0.7 }

// 人大 — 摇摆投机型
{ aggression: 0.1, cooperation: 0.8, riskTolerance: 0.4 }

// 政协 — 老狐狸型
{ aggression: 0.2, cooperation: 0.6, riskTolerance: 0.5 }
```

### 5.2 决策流程

```
① 局势评估
   输入：gameState
   输出：threatMap（威胁等级）、seatGap（席位差距）、
         leaderGap（领跑者差距）、resourceHealth（资源健康度）、
         vulnerabilityMap（自身弱点）

② 行动优先级排序（性格 × 局势 → 打分）
   · 拜访+做任务  = seatGap × (1-aggression) × urgency
   · 抢夺对手席位 = seatGap × aggression × targetVulnerability
   · 查处对手干部 = aggression × threatMap[target] × markAvailability
   · 发起/支持法案 = cooperation × billBenefit
   · 干扰对手任务 = aggression × threatMap[target] × resourceAvailability
   · 提升忠诚度   = vulnerabilityMap × (1-riskTolerance)
   · 干部任用     = resourceHealth × cooperation
   · 受贿         = riskTolerance × fundNeed

③ 贪心执行：按得分排序，依次执行直到资源耗尽
```

### 5.3 AI 人格化设计
- **性格一致性**：Ch 几乎每轮都会查处人，MI 几乎不主动进攻
- **适应局势**：玩家领先过多时，所有 AI 攻击性临时 +0.2（合纵连横）
- **有失误**：10-15% 概率做出次优选择
- **记仇**：玩家查处过 AI 干部 → 对你的 aggression +0.3 持续整局
- **示好**：低 aggression 的 AI 偶尔主动支持玩家法案

## 六、胜负条件

### 6.1 胜利条件
| 条件 | 判定时机 |
|------|----------|
| 席位过半（≥14/27） | 10 轮结算时 → 当选省长 |
| 席位领先（≥12） | 10 轮均未过半 → 险胜 |
| 延长赛胜出（≥12） | 延长 2 轮后 → 微弱多数胜 |

### 6.2 失败条件
| 条件 | 判定时机 |
|------|----------|
| 席位落后 | 10 轮+延长赛后非玩家席位最多 |
| 派系崩溃 | 所有副厅以上干部被查处解除职务（提前终止） |
| 众叛亲离 | 一半以上成员忠诚度降至 2 以下（提前终止） |

## 九、技术架构

### 9.1 技术栈

| 层 | 选择 | 说明 |
|----|------|------|
| 桌面壳 | Electron | 开发阶段 `electron .` 直接运行 |
| 逻辑语言 | 纯 JS（ES Modules） | 零依赖，可单独测试 |
| 渲染（v1） | DOM + CSS | 信息密集型 UI 最优方案 |
| 渲染（v2 可选） | Canvas 迁移 | 预留渲染接口，逻辑层不改 |
| 状态管理 | 单一 gameState + 事件订阅 | 可序列化存档 |
| 打包 | electron-builder | 最后阶段才打包 |

### 9.2 架构分层

```
┌─────────────────────────────────────────────┐
│              游戏逻辑层 (纯 JS，零 DOM)         │
│  state / turn / actions / bills / events    │
│  personnel / investigation / npc-seats      │
│  resources / bribery / victory / ai          │
│              ↕ (事件订阅/通知)                │
│              渲染接口层 (抽象)                 │
└─────────────────────────────────────────────┘
          ↙ v1 实现          ↘ v2 可切换
┌──────────────────┐  ┌──────────────────┐
│  DOM Renderer    │  │  Canvas Renderer │
│  HTML/CSS 面板    │  │  手绘卡牌/地图    │
└──────────────────┘  └──────────────────┘
```

**原则**：
- 逻辑层零 DOM 依赖
- 渲染层只读状态，不直接修改
- 用户点击 → GameAction → 逻辑层处理 → 状态变更通知 → 渲染层重绘
